# ChyguiSlide — «Чугуй слайды»

Приложение для проведения служения: песни, Библия, объявления и медиа на
втором экране. Windows 10/11 (x64). Исходный код закрыт, обновления
публикуются в этом репозитории.

Описание последней версии — в файле **`Update.md`**: программа читает его при
запуске и, если номер версии больше установленного, предлагает обновление.

## Возможности

**Песни**
- База песен с номерами и сборниками, быстрый поиск по названию и тексту.
- Редактор слайдов: куплеты, припевы и произвольные блоки, каждый слайд
  отделяется пустой строкой.
- Сборники: создание, переименование и удаление, счётчик песен, автонумерация
  внутри сборника.

**Библия**
- Книги, главы и стихи, поиск по тексту и расширенный поиск по запросу.
- Переход к следующей главе одной кнопкой, вывод стихов на экран.

**Объявления**
- Список объявлений с редактором и предпросмотром слайдов.
- Быстрое объявление в двух режимах: произвольный текст и «Убрать автомобиль»
  с готовой формулировкой и госномером.

**Трансляция**
- Плейлисты медиа, вывод видео и изображений на второй экран.
- Управление показом: переход по слайдам, завершение показа, живой
  предпросмотр.

**Оформление**
- Стили текста: шрифт, размер, цвет, жирность, выравнивание, обводка, фон и
  прозрачность, анимация перехода.
- Активный стиль применяется ко всем слайдам, есть предпросмотр.

**Второй экран**
- Выбор монитора для вывода, отдельное окно трансляции, режим постоянного
  фона для внешнего монитора.

**Горячие клавиши**
- Настройка привязок клавиш под себя, значения сохраняются в базе.

**Служебное**
- Резервные копии базы: создание копии и восстановление из файла.
- Журнал работы: отдельный файл на каждый запуск, хранятся последние 10
  файлов, быстрый переход в папку журналов.
- Проверка и оптимизация видео (перенос служебного блока `moov` в начало
  файла) через встроенные `ffmpeg` и `ffprobe`.
- Автоматическое обновление из этого репозитория.

## Системные требования

- Windows 10 или Windows 11, 64-бит.
- Права администратора не нужны: установка идёт в профиль пользователя.

## Установка

Установщик с `ffmpeg` и `ffprobe` весит больше 100 МБ, а GitVerse не принимает
`.exe` в ассетах релиза, поэтому файлы релиза — это gzip-части архива. Скрипт
`install.ps1` скачивает их, распаковывает, склеивает, сверяет SHA-256 и
запускает установщик — то же самое делает приложение при обновлении.

1. Откройте PowerShell: «Пуск» → наберите `PowerShell` → Enter.
2. Выполните одну строку:

   ```powershell
   & ([scriptblock]::Create((irm 'https://gitverse.ru/DjgaaD/ChyguiSlide/content/master/install.ps1?raw=1').TrimStart([char]0xFEFF)))
   ```

   `.TrimStart([char]0xFEFF)` убирает BOM в начале файла — без этого PowerShell
   не разберёт первую строку скрипта. Скрипт покажет версию и список изменений,
   спросит подтверждение, скачает около 266 МБ и откроет окно установщика.
   Скачанные файлы он удаляет за собой.

   Windows может предупредить: «Windows защитила ваш компьютер» — установщик не
   подписан сертификатом. Нажмите «Подробнее» → «Выполнить в любом случае».

Если удобнее файлом: скачайте `install.ps1` из репозитория и выполните
`powershell -ExecutionPolicy Bypass -File install.ps1`, либо щёлкните по файлу
правой кнопкой → «Выполнить с помощью PowerShell».

Вручную, без скрипта: скачайте из релиза все части `.gz`, склейте их в один
файл (`copy /b part1.gz+part2.gz+part3.gz update.gz`), распакуйте его как gzip
(7-Zip, WinRAR) — получится `update.zip`, а в нём установщик.

## Как работает обновление

1. При запуске программа читает описание последней версии из файла `Update.md`
   и сравнивает указанный в нём номер с установленной версией.
2. Если версия новее, появляется окно «Доступно обновление» со списком
   изменений и тремя действиями:
   - **Обновить** — скачать файлы, проверить контрольную сумму, распаковать
     установщик и установить обновление; программа перезапустится сама;
   - **Пропустить эту версию** — версия запоминается и больше не
     предлагается, но следующая версия будет предложена снова;
   - **Напомнить позже** — окно закроется, проверка повторится при следующем
     запуске.
3. Ручная проверка: «Настройки» → «О нас» → «Проверить обновление». Кнопка
   спрашивает версию в репозитории и пишет результат строкой под собой
   («У вас последняя версия…» или «Доступна версия…»); при ручной проверке
   пропущенная версия предлагается снова. Рядом показаны версия приложения,
   разрядность и система.

## Как выпустить обновление

1. Соберите установщик и задайте версию одной командой — номер записывается
   сразу в `src-tauri/tauri.conf.json` (оттуда его берут «О нас» и сравнение
   версий), `package.json` и `src-tauri/Cargo.toml`:

   ```bat
   build_installer.bat 0.2.0
   ```

   Без аргумента скрипт спросит версию (Enter — оставить текущую), а задать её
   можно и переменной окружения `APP_VERSION`. Готовый установщик появится в
   `src-tauri/target/release/bundle/nsis/`.
2. Подготовьте файлы релиза:

   ```powershell
   powershell -ExecutionPolicy Bypass -File prepare_release.ps1
   ```

   Скрипт упакует установщик в `.zip`, посчитает SHA-256 и, если архив больше
   95 МБ, нарежет его на gzip-части. В конце он напечатает готовый блок
   манифеста и список файлов из папки `release/`.
3. Создайте релиз с тегом `v<версия>` (например `v0.2.0`) и прикрепите файлы
   из папки `release/`. **Не отмечайте** «Ограничение доступа для
   неавторизованных пользователей» — иначе программа не сможет скачать файлы.
4. Проверьте ссылки на файлы: откройте релиз → «Ассеты» → правой кнопкой по
   имени файла → «Копировать ссылку». Адрес из браузера — самый надёжный,
   приложение скачивает ровно тот адрес, что указан в манифесте.
5. Замените блок манифеста в `Update.md` на напечатанный и сохраните
   изменения. Обновление появится у пользователей при следующем запуске.

### Публикация одной командой

Шаги 3–5 выполняет скрипт из папки проекта: он создаст релиз с тегом
`v<версия>`, прикрепит файлы из `release/`, подставит блок манифеста в
`Update.md` и опубликует в репозитории `Update.md` и `README.md`. Ссылки на
файлы он возьмёт из ответа GitVerse при загрузке, так что в манифест попадут
рабочие адреса.

```powershell
$env:GITVERSE_TOKEN = '<токен с правом «Запись» на репозиторий>'
powershell -ExecutionPolicy Bypass -File publish_gitverse.ps1
```

Токен создаётся в GitVerse: профиль → «Управление токенами». Пробный запуск без
публикации — `-DryRun`, проверка скачивания и сверка SHA-256 склеенных частей —
`-VerifyDownload`.

### Формат блока манифеста

Поля блока манифеста, ограничения GitVerse на ассеты релизов и правила работы с
несколькими файлами релиза описаны в файле [`Update.md`](Update.md) — там же
лежит и сам блок.
