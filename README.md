# ChyguiSlide — «Чугуй слайды»

Приложение для проведения служения: песни, Библия, объявления и медиа на
втором экране. Windows 10/11 (x64).

Установщик с `ffmpeg` и `ffprobe` лежит в
[релизах](https://github.com/DjgaaD/ChyguiSlide2/releases), описание последней
версии — в файле **[`Update.md`](Update.md)**: программа читает его при запуске
и, если номер версии больше установленного, предлагает обновление.

## Возможности

**Песни**
- База песен с номерами и сборниками, быстрый поиск по названию и тексту.
- Редактор слайдов: куплеты, припевы и произвольные блоки, каждый слайд
  отделяется пустой строкой.
- Импорт песни из презентации (`.pptx`, `.odp`) и с сайта: текст и название
  подставляются в редактор новой песни — остаётся проверить и сохранить.
- Сборники: создание, переименование и удаление, счётчик песен, автонумерация
  внутри сборника.

**Библия**
- Книги, главы и стихи, поиск по тексту и расширенный поиск по запросу.
- Переход к следующей главе одной кнопкой, вывод стихов на экран.

**Объявления**
- Список объявлений с редактором и предпросмотром слайдов.
- Быстрое объявление в двух режимах: произвольный текст и «Убрать автомобиль»
  с готовой формулировкой и госномером.

**Трансляция**
- Плейлисты медиа, вывод видео и изображений на второй экран.
- Управление показом: переход по слайдам, завершение показа, живой
  предпросмотр.
- Вывод слов в OBS источником «Браузер»: прозрачный фон, текст слайда одной
  строкой, подложка с настраиваемой непрозрачностью и оформление активного стиля —
  только песни и стихи Библии (см. «Вывод слов в OBS»).

**Оформление**
- Стили текста: шрифт, размер, цвет, жирность, выравнивание, обводка, фон и
  прозрачность, анимация перехода.
- Активный стиль применяется ко всем слайдам, есть предпросмотр.
- Готовые стили («На белом фоне», «На чёрном фоне», «Анимированный фон») и
  обои появляются при первой установке; клик по стилю в списке применяет его,
  фон включается с началом показа.

**Второй экран**
- Выбор монитора для вывода, отдельное окно трансляции, режим постоянного
  фона для внешнего монитора.

**Горячие клавиши**
- Настройка привязок клавиш под себя, значения сохраняются в базе.

**Служебное**
- Резервные копии базы: создание копии и восстановление из файла.
- Журнал работы: отдельный файл на каждый запуск, хранятся последние 10
  файлов, быстрый переход в папку журналов.
- Проверка и оптимизация видео (перенос служебного блока `moov` в начало
  файла) через встроенные `ffmpeg` и `ffprobe`.
- Автоматическое обновление из этого репозитория.

## Вывод слов в OBS

Слова слайда можно выводить в OBS источником «Браузер» — поверх видео, без
второго экрана:

1. Настройки → Трансляция → «Вывод слов в OBS»: включите опцию, при необходимости
   поменяйте порт (по умолчанию `8765`), включите подложку под текст и задайте её
   непрозрачность в процентах (по умолчанию 90 %) — и нажмите «Сохранить настройки».
2. Скопируйте адрес из поля «Адрес для источника «Браузер»».
3. В OBS добавьте источник **Браузер** (Browser), вставьте адрес и задайте размер
   того места на сцене, где должны быть слова (например, `1920×1080` на весь экран
   или `1920×200` полосой снизу).

Оформление оверлей берёт из активного стиля: цвет, шрифт, жирность, обводка и
переходы между слайдами. Слова приходят **одной строкой** (как в прежней версии
программы): строки слайда склеиваются пробелом, подпись стиха («Ин 3:16») идёт в ту
же строку — в начало или в конец, как задано в стиле. Переносы по ширине источника
делает оверлей, а размер шрифта подбирается так, чтобы слова занимали источник
целиком и не оставляли пустого места. Текст обновляется сразу — страница получает
его потоком событий, а не опросом, — и проявляется с плавным появлением, как и на
втором экране.

В трансляцию уходят **только песни и стихи Библии**. Объявления показывают в зале,
в OBS они не попадают: на объявлении оверлей гасится, чтобы в эфире не остались
слова предыдущей песни.

Дополнительные параметры адреса:

- `?w=1920&h=1080` — фиксированный размер сцены;
- `?backdrop=0.4` — подложка под текст, доля `0…1` или проценты; параметр сильнее
  настройки подложки в программе (удобно проверить другой вариант, не меняя настройки).

Если OBS работает на другом компьютере в той же сети, используйте адрес из строки
подсказки под полем (вида `http://192.168.x.x:8765/`). Сервер слушает все сетевые
интерфейсы, поэтому включайте вывод только в доверенной сети.

## Системные требования

- Windows 10 или Windows 11, 64-бит.
- По умолчанию программа ставится в профиль пользователя, и права администратора
  не нужны. Они потребуются, только если папка установки защищена (например,
  `C:\Program Files`): тогда Windows запрашивает подтверждение.

## Установка

Установщик весит около 270 МБ: внутри лежат `ffmpeg`, `ffprobe` и медиафайлы.
Скрипт `install.ps1` читает манифест обновления, скачивает файл релиза,
сверяет SHA-256 и запускает установщик — то же самое делает приложение при
обновлении.

1. Откройте PowerShell: «Пуск» → наберите `PowerShell` → Enter.
2. Выполните одну строку:

   ```powershell
   & ([scriptblock]::Create((irm 'https://raw.githubusercontent.com/DjgaaD/ChyguiSlide2/master/install.ps1').TrimStart([char]0xFEFF)))
   ```

   `.TrimStart([char]0xFEFF)` убирает BOM в начале файла — без этого PowerShell
   не разберёт первую строку скрипта. Скрипт покажет версию и список изменений,
   спросит подтверждение, скачает установщик и откроет его окно. Скачанные
   файлы он удаляет за собой.

   Windows может предупредить: «Windows защитила ваш компьютер» — установщик не
   подписан сертификатом. Нажмите «Подробнее» → «Выполнить в любом случае».

Если программа уже установлена, скрипт ставит её в тот же каталог. В защищённой
папке (`C:\Program Files` и подобных) установщик запускается с правами
администратора — Windows запросит подтверждение. Без прав тихая установка в
такой папке заканчивается «успешно», но не заменяет ни одного файла.

Если удобнее файлом: скачайте `install.ps1` из репозитория и выполните
`powershell -ExecutionPolicy Bypass -File install.ps1`, либо щёлкните по файлу
правой кнопкой → «Выполнить с помощью PowerShell».

Вручную: скачайте из [релиза](https://github.com/DjgaaD/ChyguiSlide2/releases)
файл `ChyguiSlide_<версия>_x64-setup.exe` и запустите его.

## Как работает обновление

1. При запуске программа читает описание последней версии из файла `Update.md`
   этого репозитория и сравнивает указанный в нём номер с установленной
   версией.
2. Если версия новее, появляется окно «Доступно обновление» со списком
   изменений и тремя действиями:
   - **Обновить** — скачать файл, проверить контрольную сумму, распаковать
     установщик и установить обновление; программа перезапустится сама. Если
     программа стоит в защищённой папке (`C:\Program Files`), Windows запросит
     права администратора: без них установщик не заменит файлы. Отказ от запроса
     прав обновление отменяет, программа остаётся открытой;
   - **Пропустить эту версию** — версия запоминается и больше не
     предлагается, но следующая версия будет предложена снова;
   - **Напомнить позже** — окно закроется, проверка повторится при следующем
     запуске.
3. Ручная проверка: «Настройки» → «О нас» → «Проверить обновление». Кнопка
   спрашивает версию в репозитории и пишет результат строкой под собой
   («У вас последняя версия…» или «Доступна версия…»); при ручной проверке
   пропущенная версия предлагается снова. Рядом показаны версия приложения,
   разрядность и система.

## Разработка

Стек: Tauri 2 (Rust) + TypeScript без фреймворка, SQLite (`rusqlite`),
интерфейс собирается Vite.

```bash
npm install
npm run tauri dev
```

Приложение поставляется с готовой базой `src-tauri/resources/template.sqlite`
(Синодальный перевод и «Песнь возрождения 3300»). При первом запуске на новом
компьютере этот файл копируется в каталог данных приложения под рабочим именем
`chyguislide.sqlite`; файлы `songs.sps` и `bible.json` при старте не разбираются.
Чтобы проверить первый запуск ещё раз, переименуйте или удалите рабочую базу в
каталоге данных приложения (в Windows это `%APPDATA%\com.chyguislide.app`).
Эталон обновляют копией рабочей базы после закрытия приложения — одним файлом,
без журналов `-wal` и `-shm`.

### Сборка установщика

```bat
build_installer.bat 0.2.0
```

Скрипт записывает версию в `src-tauri/tauri.conf.json` (оттуда её берут «О нас»
и сравнение версий), `package.json` и `src-tauri/Cargo.toml`, затем собирает
установщик NSIS в `src-tauri/target/release/bundle/nsis/`. Без аргумента скрипт
спросит версию (Enter — оставить текущую), задать её можно и переменной
окружения `APP_VERSION`.

### Публикация релиза

1. Соберите установщик: `build_installer.bat <версия>`.
2. Подготовьте файлы релиза:

   ```powershell
   powershell -ExecutionPolicy Bypass -File prepare_release.ps1
   ```

   Скрипт кладёт установщик в `release/` и считает SHA-256. Ключ `-Pack`
   дополнительно упаковывает его в `.zip` и режет на gzip-части — это нужно
   только для хостингов с лимитом на размер файла.
3. Опубликуйте релиз и документацию:

   ```powershell
   powershell -ExecutionPolicy Bypass -File publish_github.ps1
   ```

   Нужен [GitHub CLI](https://cli.github.com), авторизованный в аккаунте
   репозитория (`gh auth login`). Скрипт создаёт релиз `v<версия>`, загружает
   файлы из `release/`, подставляет в `Update.md` блок манифеста с настоящими
   ссылками и публикует `Update.md`, `README.md` и `install.ps1` — обычным
   `git push`, а если папка не git-репозиторий, через API GitHub. Пробный запуск
   без обращений к сети — `-DryRun`, полное скачивание файла релиза со сверкой
   SHA-256 — `-VerifyDownload`.

   Текст изменений в манифесте и на странице релиза задаётся ключом `-Notes`
   (или `-NotesFile`), а без них берётся из текущего блока `Update.md`, так что
   правки сохраняются между выпусками.

### Что не хранится в репозитории

- `src-tauri/binaries/ffmpeg-x86_64-pc-windows-msvc.exe` и
  `ffprobe-x86_64-pc-windows-msvc.exe` — каждый больше 200 МБ, а GitHub
  принимает файлы до 100 МБ. Положите их в `src-tauri/binaries/` перед сборкой.
- `Данные/` — исходные файлы Библии, сборника песен и обоев. В сборку они не
  входят: из них заранее готовится эталонная база
  `src-tauri/resources/template.sqlite` (и обои в
  `src-tauri/resources/wallpapers/`); эта база лежит в репозитории и копируется
  при первом запуске приложения.
- `release/` — файлы релиза, их создаёт `prepare_release.ps1`.

### Структура

- `src/` — интерфейс: `controller/` (окно оператора), `display/` (окно
  трансляции), `shared/`.
- `src-tauri/src/` — бэкенд: `commands.rs` (команды для интерфейса), `db.rs`
  (SQLite), `seed.rs` (установка базы из ресурсов при первом запуске),
  `updater.rs` (обновление), `windows.rs` (второй монитор), `logger.rs`,
  `obs.rs` (вывод слов в OBS), `yandex.rs` (копии на Яндекс.Диске).
- `install.ps1` — установка на новый компьютер; `prepare_release.ps1` и
  `publish_github.ps1` — выпуск версии.
- `Update.md` — машинночитаемое описание последней версии: формат блока, поля
  манифеста и правила работы с несколькими файлами релиза.
